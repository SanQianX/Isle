# V4.1 → 生产前端 UI/UX 实施契约

## 1. 设计定位

ISLE 是**地点优先**的摄影作品榜，而不是摄影师个人展、后台管理系统或小红书动态流。

用户首次打开应依次理解：`这是桂山岛` → `这里有大家分享的照片` → `哪一张现在是最美的` → `我可以投票/上传自己的照片`。所有页面以风景本身建立吸引力，排版、色彩和字重保持克制。

**来自 V4.1 的视觉 token（可微调，但必须保持相同调性）：**

| token | 暖纸白（默认） | 冷雾灰（可选） | 用途 |
|---|---|---|---|
| `--bg` | `#f8f9f6` | `#f1f4f3` | 全站主背景 |
| `--hero` | `#eaf0eb` | `#e2eae9` | 地点首屏淡色背景 |
| `--paper` | `#ffffff` | `#f9fbfa` | 表单/浅色独立区域 |
| `--ink` | `#1b2927` | `#1d3030` | 一级文字 |
| `--muted` | `#71817a` | `#708484` | 辅助文字 |
| `--line` | `#d9e1db` | `#ccd9d5` | 细分隔线 |
| `--accent` | `#31594d` | `#376760` | 小面积品牌色/投票 |
| 灯箱 | `#090d0d` | 同 | 原图查看时唯一深色背景 |

不要过度设计徽章/胶囊按钮/阴影。用留白、版式和照片比例组织内容。访问者名字显示为 `访客 #xxxxxx`，不暴露私密标识。

## 2. 路由与导航（生产不能继续 hash-page 方案）

- `/`：首选地点桂山岛的摘要型首页（可由 site featuredPlaceId 配置）；顶部地点 Hero + 目前第 1 名 + 少量高票照片 + “完整榜单”。
- `/places`：地点列表，地点图作为主视觉；空地点有“上传第一张”的清楚入口。
- `/places/new`：添加地点独立页面。
- `/places/[slug]`：某地点首页；从地点列表选中时进入。
- `/places/[slug]/ranking`：当前地点完整照片榜，明确排名、票数、作者。
- `/places/[slug]/upload`：该地点上传照片，预置所属地点。
- 原图灯箱：从 `/places/[slug]/ranking?photo=<id>` 等当前页面叠加，关闭恢复页面；链接粘贴到另一浏览器也能打开对应照片。浏览器后退 = 关闭灯箱；前进 = 重新打开。
- 点击 Logo 返回首页；导航当前态清楚；链接支持新标签；不存在的 slug 用统一 404 页面。

## 3. 页面逐屏交互

### 3.1 首页 / 地点 Hero

- 左：地区标识、地点名、简洁说明、`我也拍过这里` 主 CTA、照片数量/参与者数量（真实 DB）。
- 右：当前 No.01 作品完整比例展示（不是固定裁切大封面）、标题、上传访客码、当前得分及 ↑/↓。
- 下：No.02–04 等高不等宽摄影墙，小标题“桂山岛 · 照片榜”，`查看完整榜单`。
- 无数据时真实空态：“这里还没有照片，上传第一张”，不要无条件塞 8 张假照片。
- 首屏背景应**比照片安静**；品牌绿控制在投票、按钮和标签；投票不覆盖照片中主体。

### 3.2 地点列表

- 以“照片 + 地点名 + 照片数 + 上传人数”作为完整可点击区域（同时提供明确可访问链接）。
- 地点的封面=当前榜单最高票的照片 1200 缩略版本，保留完整构图，容器可留细微底色。
- 新增地点显示空态，但不能随意拉伸成大尺寸灰卡片；`创建地点` 按钮清楚。
- 手机端一列，桌面宽大但不拥挤，长地名/地区自动换行不溢出。

### 3.3 地点照片榜

- 标题 `桂山岛 · 照片榜`，说明“由大家共同选出”；可看到总数量。
- 第 1 名适当放大，设计上和其余照片有等级差，但不能将其它作品缩到难看。
- No.02 起：**Justified Gallery**（严格保持名次顺序）。每张图下紧跟：`02`、照片标题、`访客 #...`、score、↑/↓。
- 投票按钮占据足够触控面积，点击有真实选中状态和成功/错误反馈；数据源必须是后端。
- 票后排行榜可能重排：避免在用户快速重复投票时焦点丢失、页面突然强制跳到顶端；更新以稳定 `photo.id` key 重渲染、保留滚动锚点；`aria-live=polite` 提示成绩变化。

### 3.4 灯箱（核心页面）

- 近黑背景，全屏显示一张；图片 CSS `object-fit: contain`，保持方向与比例；照片不加遮罩滤镜。
- 标题、上传访客码、当前得票、投票、上一张/下一张/关闭在边缘轻量排列；复杂文件信息默认收起。
- 文件信息：真实原始尺寸、格式、原始文件大小、上传者、地点、照片描述、上传时间；“下载原图”。
- 打开灯箱时 `GET /api/photos/:id/original`，不是 1200px 缩略图；网络失败显示“原图无法加载，可重试”，不偷偷用缩略图顶替并声称原图。
- `1:1` 指在有足够像素映射的浏览器视图内以照片自然像素尺寸显示（合理考虑 devicePixelRatio）；支持拖拽/触摸平移；再次点击适应屏幕。
- `Escape` 关闭；`←/→` 切换；点击箭头切换；手机非缩放状态下向左/右轻扫切换；屏幕阅读器角色/label 明确；打开 focus trap，关闭将焦点还给原照片；滚动锁定/释放正确。
- 上传照片附带 EXIF/GPS 隐私告知，原图信息仅显示必要技术元数据，不在榜单暴露 GPS。

### 3.5 上传页

- 主路径“当前地点 > 上传照片”，有清楚的返回；独立页面不用弹窗。
- 区域支持多图拖入/多选，最多 30 张，单张 ≤25 MiB，JPEG/PNG/WebP；实际常量从共享配置导入。
- 选中显示缩略图、原比例、文件大小、错误状态、移除按钮；可批量添加第二次选择，避免同名不同文件被意外合并。
- 填一句说明：最长 300 字，空值允许；照片标题默认从文件名剥离扩展名并去除无意义路径，最多 80 字。
- 按每图维持 `queued/uploading/success/failed` 和进度（可接受若传输 API 提供可测进度）；并发两张，失败单图重试；已成功的不重复提交。
- 上传成功后导航到所属地点榜单，并显示上传结果；网络错误或某张图片不合格时，其余可继续完成。
- 上传前显示：原件将保留，其他访客可查看/下载且原件可能包含 GPS/设备 EXIF；提供可见确认，不静默破坏元数据。

### 3.6 创建地点页

- 地点名必填（1–60 字）；地区必填（2–80 字）；一句介绍可选（≤300 字）；输入反馈清楚。
- 同名地点返回冲突提示及跳转到已存在地点（如果可识别）；提交中避免双击。
- 创建成功进入 `/places/[slug]`，显示“上传第一张照片”空态；不出现虚假的封面、票数或旅行者数量。

## 4. Justified Gallery 算法的工程要求

### 4.1 基本算法

来自 V4.1 的 `bestPhotoRows` 作为起点，提炼成 `bestPhotoRows(items, containerWidth, opts)` **纯函数**：

```ts
type LayoutInput = { id: string; width: number; height: number };
type LayoutTile = { id: string; widthPx: number; heightPx: number; rowIndex: number };
type LayoutRow = { heightPx: number; tiles: LayoutTile[]; isLast: boolean };
```

- 输入已经按服务器排行榜排序；函数**不得改变输入顺序**。
- 容器宽度来自 `ResizeObserver`（不是只依靠 `window.innerWidth`），可减去左右 padding。
- 优化“每行目标高 335px、间距 22px、上限 440px、下限 220px、最多 5 张/行”；目标值可以按不同宽度调节，但需要测试证明结果协调。
- 行内所有图片高度一致，宽度=高度×图片展示比例；每个图片在其容器中不被拉伸/裁切；最后一行可以自然靠左，不必强行放大。
- 图片太竖导致 tile 宽度 <152px 时可加惩罚，或安排新行；面对极端竖图必须允许合理退化，而不是强行截断照片。
- 宽度 <=760px 单列；取 `width:100%`、容器高按照片比例；手机大图/榜单不裁切。
- 排序变化和窗口缩放时减少重排抖动，读取后端 `width/height` 提前预留空间，无需等 image.onload 才布局。

### 4.2 不变量

1. `inputIDs === outputTileIDs` 且顺序完全相同。
2. 每个 tile 的 `width/height` 与真实图片比例误差在浮点容忍范围内；图片不拉伸。
3. 每行使用宽度不超过容器宽度 + 1 CSS px；行间不重叠。
4. 正常行尽可能填满；最后一行允许靠左空白，禁止一张无意义的竖图占满整行而两侧留下大片空洞。
5. 设备宽度变化、单张图损坏、长标题、不同投票数不导致横向 overflow。
6. UI 排名应从左到右、从上到下展示，不得因 CSS columns/masonry 造成阅读顺序与排名不一致。

## 5. 响应式 & 无障碍

| 环境 | 基线 viewport | 关键标准 |
|---|---|---|
| Desktop | 1440×900、1920×1080 | 照片占主要宽度，Hero 不压缩照片，Justified 多列 |
| Tablet | 768×1024 | 标题/图片无溢出，布局能过渡到单列/双栏 |
| Mobile | 390×844 | 单列画面，点击按钮可够到，固定导航不遮挡 |
| Narrow Mobile | 360×780 | 无水平滚动，长中文标题不撑宽容器 |
| Mobile WebKit | iPhone 13 或相近 Playwright device | 浏览器可点击、滚动、上传、灯箱触摸切换 |

- 触控交互目标建议 ≥44×44 CSS px；至少符合 WCAG 2.2 AA，尤其颜色对比、键盘焦点和可见 focus。
- 图片要有准确 alt（无含义装饰图 alt 为空），按钮以语义 HTML 为主；`aria-pressed` 表示投票选中，不以颜色作为唯一提示。
- `prefers-reduced-motion` 不出现强制动效；移除原型中的不必要动画。
- 空态和错误态也必须设计，而不是只验证“有图片很漂亮”。
