# 视觉基线审批记录

基线由 `npm run test:visual` 生成，本地副本写入 `e2e/__screenshots__/local/`（已 gitignore）。
**权威基线在 Linux CI 生成**，因为 Windows 与 Linux 的字体栅格化不同，混用会产生永久假回归（ADR-007）。

## 2026-10-20 · 触控目标修复引起的一次基线更新

**变更内容**：`.breadcrumb a` 获得 `min-height: 24px`（WCAG 2.2 AA 触控目标最小尺寸）。

**可见影响**：面包屑行高由 17px 增至 24px，其下方内容整体下移 **7px**。页面结构、字体、配色、照片排布均无变化。

**审查方式**：
1. 先看 diff 图确认差异**遍布全页但布局完全一致** —— 排除了重排与错位的可能，指向整体位移。
2. 测量确认位移量恰为 7px，与面包屑行增高吻合。
3. 裁出新基线的页头区域逐像素确认：**激活导航的下划线位置正确**，无异常线条。

**同批修复的一个真实缺陷**：触控热区最初用 `::after` 实现，而 V4.1 样式表已用 `::after` 绘制激活下划线，两条规则争夺同一个伪元素，**把下划线挪到了页眉顶端**。已改用 `::before`，两者不再冲突。

**结论**：本次基线更新是预期变化，非回归。触控目标尺寸由 `e2e/a11y/accessibility.spec.ts` 的专项用例守护，不会回退。

## 2026-10-20 · Linux 权威基线首次生成并入库

**背景**：本文件此前记录的都是本地（Windows）基线的变更。仓库里**一张基线都没有**——Windows 副本在 `e2e/__screenshots__/local/`，已 gitignore。于是 CI 的视觉任务每次都失败，理由是「快照不存在」，而它生成了什么从未被审查。这正是 ADR-007 说的「权威基线在 Linux CI 生成」一直没有落地的那一步。

**变更内容**：把 CI 在 `ubuntu-latest` 上生成的 **55 张 Linux 基线**（11 张 × 5 个浏览器项目）入库到 `e2e/__screenshots__/<project>/`。

**审查方式**：
1. 逐张目视核对了首页（chromium / mobile-webkit）、完整榜单（webkit）与上传失败态（chromium）：版式、字号、配色、照片排布、投票控件位置均与设计意图一致，没有错位、重叠或空白。
2. 核对了**可复现性**：页头那个随机访客码被遮罩（白框），而照片署名里的 `访客 #xxxxxx` 来自种子脚本的**确定性派生**（`sha256(label)`），所以每次运行都一样——这正是基线能逐像素比较的原因。
3. 核对了**字体**：Linux 上中日韩字形由 runner 镜像的字体渲染，与 Windows 的栅格化不同，所以这套基线只属于 Linux；本地运行仍然写入 `local/`，两套不会互相污染。

**结论**：这是**首次**入库的 Linux 基线，不是对既有基线的更新，因此不存在「用新截图覆盖旧真相」的问题——此前仓库里根本没有可比对的东西，而现在的每张图都经过上面的目视核对。

**后续规则**：基线只由 CI 生成、只经人工审查后入库。CI 里的视觉任务**不做** `--update-snapshots`：缺少基线时它会失败，并把生成的图作为 artifact 上传，等人看过再说（`DEPLOY_RUNBOOK` §「截图基线审批流程」）。
